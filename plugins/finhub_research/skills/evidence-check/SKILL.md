# Evidence Check（数字可信度核验）

## 定位

金融智能体的生死线是**数字可不信**。本技能是研究闭环的"质量门"：任何研究交付物（报告、晨报、观点、模型结论）对外输出前，先跑一遍逐数字核验，产出可审计的证据附录。**宁可少一个数字，不可多一个无来源的数字。**

**触发词**：check evidence / 核验 / 证据检查 / 数字可信吗 / 来源呢 / verify / 交付前检查 / evidence-check。

## 核验流程

### Step 1：提取全部数字声明

扫描交付物，列出所有涉及"事实性数字"的语句——价格、涨幅、市值、营收、利润、增速、比率、目标价、估值倍数、宏观数据。逐条编号（`[D1]`、`[D2]`…）。

### Step 2：逐条归因

对每个数字回答四问：

| 问题 | 通过标准 | 不通过的处理 |
|---|---|---|
| **来源** | 能指出具体数据源/工具（FMP / Yahoo / finhub-data / SEC filing / WebSearch 页面） | 标注 `[待补充来源]`，禁止直接外发 |
| **时间** | 知道数据拉取日期（`as of`），时效性符合用途 | 过期的标 `[数据陈旧]`，提示更新 |
| **口径** | 知道单位、货币、区间（TTM/季度/财年）、是否经调整 | 口径不明降级为 `[估算]` |
| **真伪** | 是"已查证数据"还是"模型推算/估算" | 估算一律标 `[估算]` + 写清假设 |

### Step 3：区分证据等级

- **已查证**：直接从数据工具/SEC/权威页面取到的数值 → 可正常引用
- **模型推算**：由模型计算的估值、DCF 结果 → 必须附假设与敏感性
- **估算/推测**：agent 或第三方的主观判断 → 必须显式标注并给推理链
- **无法取得**：明确告知缺数据，不编造

### Step 4：证伪条件核查

对每个结论性数字（目标价、评级、观点），确认交付物里写明了"什么证据会推翻它"。没有证伪条件的结论，标记为 `[待补证伪条件]` 并建议补上。

### Step 5：输出证据附录

在交付物末尾追加（或单独输出）证据附录：

```markdown
## 证据附录
| # | 数字/结论 | 来源 | 拉取时间 | 口径 | 证据等级 |
|---|----------|------|---------|------|---------|
| D1 | ... | FMP fundamentals | 2026-08-31 | TTM, USD | 已查证 |
| D2 | ... | 模型推算 | — | 假设见 §假设 | 模型推算 |

**估算与假设**：列出所有 [估算] 项及其假设。
**数据缺口**：列出未能取得、影响结论的数据。
**证伪条件**：列出推翻关键结论的具体事件/数据阈值。
```

## 集成方式

- 在 `research-loop` 阶段④报告产出后、对外交付前，强制执行本技能
- 对 `morning-note`、`initiating-coverage`、`earnings-analysis`、`idea-generation` 的输出同样适用
- 证据附录随交付物一起存 `results/`，命名 `*_evidence.md`

## 关键纪律

1. **不编造来源**：宁可标 `[待补充来源]`，绝不写一个不存在的链接或数据源
2. **不扩大来源原意**：来源只支持"某数字存在"，就不能引申为"趋势确认"
3. **区分"一方称"与"已证实"**：新闻/研报里的数字标注"一方称（X 报告）"，官方数据才标"已查证"
4. **用户提供的数字**单独标注 `[用户提供]`，不冒充系统查证
5. 无法核验的核心数字若会改变结论，明确告知用户影响，等待用户决定，不静默放行
